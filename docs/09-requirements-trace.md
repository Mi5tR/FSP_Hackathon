# Соответствие ответам постановщиков

Каждый пункт сессии вопросов и ответов (Q&A «Лидеры цифровой трансформации 2026», задача ФСП) сопоставлен
с реализацией. Автотесты на эти требования — `backend/tests/test_qa_requirements.py` и `backend/tests/test_e2e.py`.

## Обязательный минимум MVP

| Требование | Как выполнено | Где |
|---|---|---|
| Кабинеты кандидата и работодателя | Два кабинета с разграничением ролей (JWT, `require_candidate` / `require_employer`) | `frontend/src/pages/*`, `backend/app/api/candidate.py`, `employer.py` |
| Поиск и подбор | Подборка по потребности и поиск по всему банку кандидатов | `GET /employer/needs/{id}/matches`, `GET /employer/candidates` |
| Первичный тест присваивает грейд | Адаптивный тест (IRT 2PL + CAT) по категории, 12–22 задания до 20 минут, решение по медиане апостериорного θ | `services/testing/cat.py`, `service.py` |
| Автоматическая категоризация | Категория «специализация · грейд» по итогам теста; работодатель сначала видит карточки категорий, затем кандидатов | `ranking.group_categories`, `NeedPage.tsx` |
| Объяснимый подбор | Процент, откалиброванная вероятность, 6 блоков, покрытие каждого требования, флаги | `ranking.score_candidate`, `match.tsx` |
| Адресное приглашение | Позиция, вилка, описание, способ связи, снимок соответствия, суточный лимит по доверию, срок 14 дней, статусы до оффера и выхода | `POST /employer/invitations` |
| Одинаковые задачи не расходятся между кандидатами | Параметрические семейства: числа, имена, код и порядок ответов генерируются заново, ответ вычисляется программно и не уходит на клиент | `services/testing/item_bank.py` |
| Документация с обязательным перечнем | См. раздел «Документация» ниже | `docs/` |
| Десятки одновременных пользователей | Нагрузочная проверка: 60 запросов в 50 потоков — 0 ошибок, p95 1,4 с | [05-architecture.md](05-architecture.md) |
| Профиль: форма или PDF с автораспознаванием; автогенерация стандартизированного PDF-профиля | Разбор PDF-резюме в поля; генерация PDF по единому шаблону (`GET /candidate/profile/pdf`), работодателю — обезличенная версия до согласия | `services/profile_pdf.py`, кнопки «Скачать PDF-профиль» и «PDF» |
| Правила видимости данных | Обезличенные карточки, контакты только после согласия, настройки приватности | `api/common.py` |

## Тест, грейд, вакансия

| Ответ постановщиков | Реализация |
|---|---|
| Грейд только по первичному тесту категории, не по вакансии и не по ФСП | Грейд меняет только `service.finish` по итогам теста на грейд. Проверка навыка и ФСП грейд не меняют |
| Достижения ФСП — ранжирование внутри категории | Блок-бонус ФСП после агрегации, сортировка сначала по точности категории |
| Неподтверждённый грейд показывать со статусом и опускать, не скрывать | Профиль остаётся в выдаче с заявленным грейдом и пометкой «не подтверждён», штраф ×0.6 и сортировка ниже подтверждённых в своей категории; пунктирная рамка в карточке |
| Кандидат сам выбирает грейд, подсказка по резюме допустима | Выбор в опросе из 6 ступеней. `GET /candidate/grade-hint` — ML-подсказка по стажу, стеку, призовым местам ФСП и опроснику самооценки, с пометкой «это не оценка» |
| Неподтверждённый грейд: показывать или скрывать с обоснованием | По умолчанию показывается; кандидат сам может скрыть профиль до пересдачи (`privacy.show_unconfirmed`) |
| Повышение — отдельным тестом | При уверенном подтверждении (`upgrade_eligible`) система сама предлагает тест на ступень выше, доступный сразу (30 дней). Автоповышения нет |
| Кулдаун; провал и уход ниже без сжигания попытки | Смена подтверждённого грейда — раз в 90 дней; повтор того же уровня после неудачи — через 30 дней; тест на уровень ниже — сразу. Неподтверждённый грейд кулдаун не запускает |
| «Отрасль» = IT-направление | 6 ИТ-направлений и 8 специализаций: Backend, Frontend, Mobile, Data/ML, Аналитик, QA, DevOps, ИБ. Грейды Intern, Junior, Junior+, Middle, Middle+, Senior |
| Грейд — уровень навыков, а не стаж (ответ VS.1) | Грейд присваивает тест; стаж — атрибут профиля и признак для подсказки |
| Тест единый под категорию, но не одинаковый пул (VS.5) | Пул семейств по специализации, варианты генерируются заново, адаптивный выбор из топ-4 |
| Регулярные задания адресно (E09) | Система выбирает для кандидата «задание для вас» по навыку с наименьшей уверенностью; счётчик новых заданий в меню |
| Задания работодателя: эталон проверяет система, открытый ответ — работодатель | `answer_type = exact` с `reference_answer` (варианты через «|», нормализация регистра и пробелов) проверяется сразу; `open` оценивает работодатель 1–5. Оценки становятся доказательством навыков. Экран «Задания» |
| Импорт чужих вакансий не нужен | Не реализуется: вакансии создают только работодатели платформы |
| Зарплата: гросс или нетто — подписать | Везде подписано «gross, до вычета НДФЛ»: формы, приглашения, вакансии, ожидания кандидата |

## LLM, песочница, антисписывание

| Ответ постановщиков | Реализация |
|---|---|
| LLM можно (в т.ч. зарубежные), использование описать; ML и NLP — преимущество | **Внешних LLM в рабочем контуре нет.** ML/NLP на scikit-learn без GPU: специализация по тексту, нечёткие навыки, подсказка грейда, изотоническая калибровка ([08-libraries.md](08-libraries.md)). Офлайн-роль LLM (новые семейства с калибровкой как pretest) описана в [01-concept.md](01-concept.md) |
| GPU на стенде нет | Всё считается на CPU |
| Песочница, прокторинг, защита от LLM — плюс | «Знаниевые» задания с малым числом формулировок весят в оценке вдвое меньше. Прокторинг «лайт»: уходы с вкладки, попытки копировать условие (копирование заблокировано), подозрительно быстрые ответы. Работодатель видит сводку «тест пройден чисто / есть сигналы» — как сигнал, без влияния на θ. Лимит времени на задание и запрет поздних ответов |
| Задачи прошлых соревнований ФСП — с защитой от преимущества решавших | В тест не включаются: банк состоит из собственных генерируемых семейств |

## ФСП и ФСП ID

| Ответ постановщиков | Реализация |
|---|---|
| Подтверждённый профиль — данные из ФСП ID, а не самозаявление | Достижения импортируются только из реестра при входе или привязке через ФСП ID |
| Имитировать привязку и вход, скелет интеграции | OIDC Authorization Code: экран имитированного ФСП ID, одноразовый code, проверка state; `KeycloakOidcProvider` включается переменными окружения. Схемы — [06-fsp-integration.md](06-fsp-integration.md) |
| Keycloak в Docker Compose не ждут | Не поднимается |
| Альтернативная регистрация по email | Есть, параллельно с ФСП ID |
| Ранжировать дисциплины не надо, все соревнования равно важны; можно учитывать профильность (E08) | Уровень мероприятия не взвешивается; коэффициент профильности дисциплины для специализации 0.6–1.0 (ИБ-специалисту CTF важнее робототехники) |
| Данные ФСП: участия, места, разряды, дисциплины | Импортируются мероприятие, дисциплина, дата, место, число участников, роль, навыки, спортивный разряд |
| Учитывать число соревнований и результативность, не давать набить профиль онлайн-явками | Победа > призовое > топ-10 > участие; вклад участий ограничен 0.5 |
| Срок давности — по желанию | −15% за год, не ниже 50% |
| Вклад в командный хакатон честно не выделить | Роль в команде только отображается, в балл не входит |

## Подбор, контакты, аудитория

| Ответ постановщиков | Реализация |
|---|---|
| Категоризация, объяснимый подбор, адресное приглашение + оригинальность | Обратная механика: работодатель выбирает категорию, потом человека; настраиваемая модель релевантности; зарплатный сигнал без раскрытия ожиданий; фильтр «не ниже моих ожиданий»; уведомления о новых кандидатах; несколько позиций одному кандидату; оффер и выход на работу |
| Защита от фиктивных вакансий и ATS — концепция, плюс (FTT.5) | Реализованы: оценка доверия 0–100, суточные лимиты, жалобы с автоприостановкой, флаг вилки-приманки; Huntflow API v2 — передача кандидатов и этапов, вебхук, импорт вакансий |
| ФИО и места работы показывать допустимо (VS.4) | До согласия карточка обезличена (выбор в пользу приватности по 152-ФЗ); контакты закрыты всегда до согласия |
| Несколько категорий у кандидата — плюс (VS.2) | В MVP одна категория; несколько — в плане развития |
| Контакты открываются пригласившему после принятия; отзыв доступа — плюс | Реализовано. Кандидат может отозвать и вернуть доступ в карточке приглашения; работодатель снова видит обезличенную карточку |
| Чат на платформе — плюс | Переписка по приглашению для обеих сторон, без раскрытия контактов; счётчики непрочитанного в навигации |
| Проверка компании — добровольная метка доверия | Проверка ИНН по контрольной сумме → метка «ИНН проверен» у кандидата. Основной сценарий не блокируется |
| Правовой минимум, 152-ФЗ | Согласие на обработку при регистрации и на экране ФСП ID, отдельное согласие на публикацию, отзыв в любой момент |
| Несовершеннолетние: с 15 лет лёгкий труд, согласие родителей | Дата рождения в профиле; до 15 лет публикация запрещена; 15–17 — только с согласием законного представителя (ФИО, контакт); работодатель видит отметку «до 18, только лёгкий труд (ст. 63 ТК РФ)» |
| Аудитория — и начинающие участники ФСП, и опытные специалисты | Грейды от Intern до Senior с промежуточными Junior+ и Middle+; ФСП — бонус, а не фильтр |
| Дизайнеры — плюс, приоритет техническим ролям (WA.2) | Приоритет техническим специализациям; для дизайнеров нужна иная форма проверки (портфолио + разбор кейса), вынесено в развитие |

## Проверка жюри и приёмка

| Ответ постановщиков | Реализация |
|---|---|
| Жюри само проходит тесты, регистрация с нуля не обязательна, демо-режим допустим | «Быстрый вход» на странице входа создаёт чистый аккаунт соискателя или работодателя без почты; демо-аккаунты с готовыми данными |
| Свой набор пар и процедура валидации | Синтетическая популяция с известной истиной, прогон через реальный код, отчёт — [02-validation.md](02-validation.md) (`python -m scripts.validate`) |
| Разделяющая сила и воспроизводимость | Точность грейда, матрица ошибок, каппа повторного прохождения, атака «слитый ключ» — в отчёте валидации |
| Стенд 32–64 ГБ RAM, ~8 CPU, без GPU | Укладываемся: 4 контейнера, расчёты на CPU |
| Питч 10 минут, видео вместо стенда допустимо (E10) | Презентация — `docs/ФСП_Карьера_презентация.pptx` (17 слайдов по шаблону ЛЦТ-2026, команда из двух человек) |
| После дедлайна идею не менять | Фиксируем коммитом; упавший контейнер поднимается `docker compose up -d` |
